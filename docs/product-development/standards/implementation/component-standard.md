# Vue 组件开发规范

本文面向产品开发人员，用于约束 Vue 组件在设计、实现和维护上的一致性。

## 1. 基本原则

- 一个组件只负责一个清晰职责。
- 组件优先表达业务语义，不优先堆叠技术细节。
- 组件对外接口必须稳定、明确、可复用。
- 状态尽量局部化，减少跨层级隐式传递。
- 组件边界要清晰，不把页面逻辑、数据请求和展示逻辑混写在一起。

## 2. 组件设计

### 2.1 优先拆分职责

一个组件如果同时承担展示、请求、校验、状态管理和副作用处理，应优先拆分。

### 2.2 Props 和 Emits 要明确

- `props` 用于输入数据和配置。
- `emits` 用于向外传递用户交互和状态变化。
- 不要直接修改 `props`。
- 复杂对象参数要定义类型，不要用宽泛对象代替。

### 2.3 Slot 只承载可扩展内容

- `slot` 用于扩展展示，不用于承载核心业务流程。
- 默认插槽和具名插槽的语义要稳定。
- 插槽参数要保持最小且清晰。

## 3. 状态与响应式

### 3.1 状态放在最小作用域

- 能放在局部就不要提升到全局。
- 只在多个组件共享时才引入共享状态。
- 临时状态和持久状态要分开管理。

### 3.2 响应式对象要克制

- `ref`、`reactive`、`computed` 各司其职。
- 不要把本可静态化的数据做成响应式。
- 派生状态优先用 `computed`，不要重复维护。

## 4. 事件与副作用

### 4.1 副作用集中处理

- 请求、订阅、定时器、埋点、通知和跳转应集中管理。
- 不要在模板表达式里写副作用。
- 生命周期钩子里只放必要副作用。

### 4.2 事件语义要稳定

- 事件名要表达“发生了什么”，不要表达“怎么做的”。
- 事件参数要结构清晰，避免隐式依赖父组件内部状态。

## 5. 渲染与性能

- 长列表要考虑虚拟滚动或分页。
- 重计算逻辑优先缓存或拆分。
- 条件渲染要避免反复创建重型子树。
- 高频更新的数据要控制粒度。

## 6. 工程约束

- 组件文件、样式文件和测试文件命名保持一致。
- 共享组件应避免携带页面级路由或业务耦合。
- 公共组件要补齐基础示例和使用说明。
- 复杂组件优先提供受控用法。

## 7. 开发检查

- 组件是否只承担单一职责。
- `props`、`emits`、`slot` 是否清晰。
- 是否存在不必要的深层嵌套状态。
- 是否存在模板中的副作用。
- 是否存在可拆分的重复逻辑。
