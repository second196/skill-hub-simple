## 3. 功能描述

### 3.1 功能目标与范围

平台应让授权用户和目标运行时获取已发布 Skill，同时安装或配置对应 Tracker，记录安装实例，支持安全更新、失败恢复、版本回退和高危撤回。

首期默认运行时矩阵为：Codex CLI、Codex 的 VS Code/Cursor/Windsurf 扩展，以及 Claude Code 的 OTLP 运行数据上报；安装主机支持 Witty 已验证的 Bash 和 PowerShell 路径。未被调研材料证实的 Claude Code IDE 扩展不纳入首期默认承诺。运行时、适配器、能力和启用状态必须可配置，后续新增或停用运行时不能改变历史安装记录。

本 Feature 不负责 Skill 资产注册、评测执行或 Agent 业务执行；它消费已发布版本，并为运行观测 Feature 产生安装、切换、回退和健康状态。

### 3.2 原子需求清单

#### `requirement-skill-distribution-installation`

用户应能指定 Skill、版本和运行时获取已发布版本，并获得明确的安装结果。草稿、发布门禁失败、已撤回或不可分发版本不得作为安装目标。

验收条件：结果包含目标 Skill、版本、运行时和成功/失败原因；不可安装版本会说明阻断原因。

#### `requirement-skill-tracker-companion-installation`

获取 Skill 时应同时安装或配置对应 `skill-tracker`。安装结果必须分别展示 Skill、Tracker、配置、运行时支持和最近健康状态；Tracker 未完成时不能标记为完整安装。

验收条件：用户能分别识别 Skill 和 Tracker 状态，并能定位 Tracker 安装或配置失败原因。

#### `requirement-skill-installation-instance`

平台应记录安装实例对应的 Skill、不可变版本、目标 Agent、主机或逻辑实例、运行时、环境、安装时间、当前启用状态和最近健康信息。内容不同的版本不得合并为同一安装实例。

验收条件：用户能查看指定目标当前启用版本、Tracker 状态和最近健康信息。

#### `requirement-skill-version-switching`

更新前必须识别当前启用版本并保留可回退版本。新 Skill 和对应 Tracker 完成下载、安装、配置及可用性确认后，才可停用旧版本并启用新版本；平台必须记录切换前后版本和结果。

验收条件：成功更新后目标实例启用新版本且旧版本可识别为停用或回退候选；未确认新版本前旧版本仍可用。

#### `requirement-skill-installation-failure-recovery`

下载、安装、配置、可用性确认、停用旧版本或启用新版本任一步骤失败时，旧版本必须保持或恢复启用。若不存在可用旧版本，不得启用未完成确认的新版本，必须标记不可用并要求人工处理。失败阶段、失败原因、回退结果、切换前后版本和当前状态必须上报；离线期间事件进入待上报队列，恢复后补报且不重复记账。

验收条件：失败后旧版本保持或恢复启用；无旧版本时不会误启用新版本；失败和回退结果在平台可查询。

#### `requirement-skill-emergency-revocation`

发现高危安全或行为问题时，授权管理员应能阻断新增安装，并停用授权范围内的存量实例。平台必须记录撤回原因、影响范围、执行结果和未成功停用的实例。

验收条件：撤回后不可新增安装；授权范围内实例状态可查询；部分失败不会被标记为全部成功。

### 3.3 运行时配置与默认矩阵

| 运行时/形态 | 默认状态 | 默认能力 | 配置要求 |
| --- | --- | --- | --- |
| Codex CLI | 启用 | Skill 获取、安装和运行数据接入 | 可按组织/项目/环境启停 |
| VS Code、Cursor、Windsurf 扩展 | 启用 | Codex 相关安装和运行数据接入 | 每个扩展形态独立配置 |
| Claude Code OTLP | 启用 | 运行数据上报 | 可独立配置上报策略 |
| 未被材料证实的 Claude Code IDE 扩展 | 默认不承诺 | 无 | 后续经验证后才能加入矩阵 |
| Bash、PowerShell 安装主机路径 | 启用 | 安装和更新脚本入口 | 可按环境配置 |

运行时矩阵的启停、适配器版本、能力状态和生效时间必须可查询。停用运行时不得删除既有安装、运行或审计数据。

### 3.4 异常与边界

- 目标版本未发布、已撤回、被授权范围阻断或不匹配运行时能力时，安装必须失败并说明原因。
- Skill 安装成功但 Tracker 安装失败时，整体状态为不完整安装，不得伪装为健康。
- 平台不可用时，本地必须保留安装失败、切换和回退事件；恢复后补报。
- 回退本身失败时标记需要人工处理，并持续上报当前状态。
- 紧急撤回只影响授权范围内对象，跨范围操作必须经过对应权限校验。

## 4. 非功能性需求

| 类型 | 要求 | 说明 |
| --- | --- | --- |
| 可靠性 | 更新失败不得破坏可用旧版本 | 无旧版本时进入人工处理状态 |
| 可恢复性 | 离线状态事件可补报且不重复记账 | 适用于安装、切换、回退和撤回 |
| 兼容性 | 首期运行时矩阵可独立启停和扩展 | 未验证的运行时能力必须显式标记 |
| 可追溯性 | 安装实例和版本切换可关联到发布版本 | 不使用名称或最新版本推断 |
| 安全 | 安装和撤回遵循授权范围和最小权限 | 高危撤回必须审计 |
