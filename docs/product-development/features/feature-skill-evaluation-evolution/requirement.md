## 3. 功能描述

### 3.1 功能目标与范围

平台应管理可复现的评测资产和质量问题，基于运行证据形成 Skill 进化候选，执行复测和回归，支持人工审核、灰度发布、质量监测和自动回退。评测结果、候选差异、审核决定和回退证据必须与明确的 Skill 版本关联。

本 Feature 不直接覆盖已发布版本，不在缺少真实判定依据时宣称业务准确率，不允许高风险候选绕过人工审核或自动全量发布。

### 3.2 原子需求清单

#### `requirement-evaluation-asset-versioning`

评测套件、案例、数据集、判定器、运行配置和报告应能独立版本化。每次评测必须记录 Skill 版本、评测资产版本、运行时、模型、环境和执行时间。

验收条件：用户能从结果定位所有评测条件；评测资产变更不会覆盖历史结果。

#### `requirement-multi-runtime-controlled-evaluation`

指定 Skill 版本应能在受控的运行时、模型和环境中重复评测。不同条件的结果不得无条件混合。

验收条件：相同条件可以复跑和比较；条件不同的结果被区分并显示差异。

#### `requirement-static-quality-findings`

平台应支持对 Skill 版本执行静态质量检查，并记录规则标识、严重程度、证据、说明和修复建议。平台必须区分静态问题、评测失败、运行失败、模型异常、工具异常和采集异常。

验收条件：质量问题能定位到检查规则和证据，并能区分问题来源。

#### `requirement-evolution-candidate-version`

平台可基于用户反馈、已确认问题或评测结果形成 Skill 进化候选。候选必须标明基线版本、内容差异、来源证据、生成时间和状态，不能覆盖已发布版本。

验收条件：用户能查看候选相对基线的变化和依据；候选与生产版本相互独立。

#### `requirement-evolution-regression-and-review`

候选发布前必须执行适用的静态检查、回归案例和评测，并展示相对基线的变化。涉及权限变化、外部写操作、质量下降、新运行时兼容性变化或高风险标记时，必须人工审核；团队范围提升至更大范围时必须进行二次审核。

验收条件：候选发布前具备可查询的复测和审核证据；高风险候选不能绕过人工审核。

#### `requirement-release-canary-and-rollback`

平台应支持候选版本在部分安装实例或授权范围内灰度，并能回退到此前已发布版本。默认灰度范围为符合条件实例的 10%，向上取整且至少 1 个实例；默认观察 24 小时且至少累计 30 次 Skill 调用。灰度期间发生以下任一情况时应自动回退并上报证据：错误率较基线增加 2 个百分点；基线大于 0 时错误率相对增加 20%；基线为 0 时错误率达到 2%；有效评分下降 5 个百分点；出现高危或严重问题。

以上灰度比例、观察时间、最小调用数、基线条件和回退阈值必须可按公司、项目和环境配置，配置需要版本化并记录生效范围和时间。无法满足相同基线条件或样本不足时，不得自动扩大灰度或全量发布。

验收条件：用户能查看灰度范围、当前版本、观察状态、触发指标和回退记录；阈值调整后使用新策略版本，不修改历史决策。

#### `requirement-evaluation-truth-disclosure`

首批评测沿用结构化 LLM Judge 评分口径：人工修正分优先，未完成修正时使用机器评分。没有业务回执或脚本断言时，平台不得将评分称为业务准确率；估算结果必须显式标记为估算。

验收条件：报告能展示评分来源、是否人工修正、判定条件和估算标记；用户不会将模型评分误认为业务真值。

### 3.3 发布策略与默认值

| 配置项 | 默认值 | 调整约束 |
| --- | --- | --- |
| 自动发布范围 | 仅低风险白名单候选 | 白名单规则必须版本化并可审计 |
| 有效评测样本 | 至少 30 个案例 | 组织可提高门槛，不得绕过必需评测 |
| 灰度比例 | 符合条件实例的 10%，向上取整且至少 1 个 | 可按授权范围配置 |
| 观察窗口 | 24 小时且至少 30 次调用 | 时间和调用门槛均满足后才能扩大 |
| 错误率回退 | +2 个百分点；基线大于 0 时相对 +20%；基线为 0 时达到 2% | 可配置，必须记录策略版本 |
| 有效评分回退 | 下降 5 个百分点 | 可配置，需保持评分口径一致 |
| 高危/严重问题 | 立即回退并上报 | 不允许配置为自动放行 |
| 比较基线 | 同一授权范围当前稳定发布版本 | 运行时、模型、工具、任务集和判定器需可比 |

### 3.4 异常与边界

- 评测条件不完整、判定器不可用或样本不足时，结果保持不可比较，不得自动放大发布范围。
- 自动生成候选或自动完成评测不等于自动发布；高风险候选必须人工审核。
- 自动回退失败时必须标记需要人工处理并继续上报，不得标记为回退成功。
- 不存在可用旧版本时不得启用未完成确认的新版本。
- 发布、灰度、回退和审核证据不可被候选新版本覆盖或删除。

## 4. 非功能性需求

| 类型 | 要求 | 说明 |
| --- | --- | --- |
| 可复现性 | 结果关联完整评测条件 | 条件缺失时阻止直接比较 |
| 可追溯性 | 候选、基线、评测、审核和回退证据可关联 | 历史决策不可被新策略覆盖 |
| 安全 | 高风险候选不得自动放行 | 审批人和申请人分离 |
| 可配置性 | 发布、灰度和回退策略支持范围化和版本化 | 后期调整必须审计 |
| 可靠性 | 回退结果和失败状态持续上报 | 失败不能伪装成功 |
