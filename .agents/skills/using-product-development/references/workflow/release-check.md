# 发布检查阶段

阶段入口：`release-check`

## 1. 阶段目标

发布前汇总变更范围、验证证据、兼容性风险、灰度方案、监控、回滚方式和人工确认项。

这是只读检查阶段，不替代验证，不自动发布、合入或接受风险。

## 2. 阶段流程

```text
确认发布对象
-> 汇总变更范围
-> 汇总验证证据和缺口
-> 检查兼容性与运行风险
-> 检查灰度、监控和告警
-> 检查回滚条件和方式
-> 列出人工确认项
-> 输出发布建议
-> 停止
```

## 3. 检查输入

发布对象必须明确为 Feature、分支、commit、PR、版本范围或发布变更清单。读取：

- `.product-development/features/feature-<featureId>/state.md` 和 `change-log.md`；
- 需求、方案和实施计划；
- 当前 diff 和关键文件；
- 验证矩阵和验证证据；
- 真实部署、监控、灰度和回滚配置。

## 4. 检查内容

- 变更范围是否与批准范围一致；
- 所有高风险需求是否有验证证据；
- 是否影响公共 API、Provider、权限、数据、状态、构建或发布链路；
- 是否需要迁移、兼容分支或分批发布；
- 灰度比例、观察窗口、成功指标和告警是否明确；
- 回滚触发条件、操作步骤和数据恢复方式是否明确；
- 未验证项、剩余风险和负责人是否列出；
- 发布、合入和风险接受是否已有人工确认。

## 5. 输出

至少输出：

- 发布检查对象；
- 变更范围摘要；
- 已执行、失败、未执行和无法执行的验证；
- 兼容性和运行风险；
- 灰度、监控和告警；
- 回滚条件和方式；
- 必须由人确认的事项；
- 建议：可以进入人工发布决策、暂不建议发布或无法判断。

“可以进入人工发布决策”不等于 Agent 代替负责人批准发布。

## 6. 阶段停止

发布检查结论输出后停止。不得修改代码、配置、发布脚本，不得自动合入、发布或回滚。
