# 阶段入口识别

## 1. 先分流

普通问答、解释、翻译和与仓库无关的事务为 `non-product`，不读取阶段流程。涉及研发产物、源码、测试、发布或研发文档时进入七阶段。输入尚未绑定已确认 Feature 时，先进入 `requirement` 的 Work Item 分解子流程；来源、文件类型和是否已有长文档都不能跳过该步骤。

## 2. 入口判断

| 主要动作 | 阶段 | 文件权限 |
| --- | --- | --- |
| 把原始描述整理成需求事实和验收标准 | `requirement` | 需求产物和控制记录 |
| 比较方案、设计接口、分析影响面、写实施计划 | `design` | 方案双产物和控制记录 |
| 修改源码、测试或配置 | `implementation` | 已授权实现范围 |
| 只找问题、风险和建议 | `review` | 只读 |
| 运行检查并给出证据 | `verification` | 只读功能文件 |
| 判断发布准备、兼容和回滚 | `release-check` | 只读 |
| 维护已确认文档 | `documentation` | 明确授权文档 |

用户同时提出多个阶段时：

1. 如果明确要求连续执行，先完成最早阶段，在每个必须人工确认的门前停止。
2. 如果没有连续授权，只执行当前最先需要的阶段。
3. “写设计文档”属于 `design`，默认生成方案和实施计划，不降级为普通 `documentation`。
4. 实现过程中必要的任务验证属于实现子步骤，不自动进入独立 `verification`。
5. 实现内部的规范符合性和代码质量检查属于实现子步骤，不自动进入独立 `review`。

## 3. 不明确时

只问一个能决定阶段、Work Item/Feature 范围或文件写入权限的问题。不要一次提出整套问卷。
